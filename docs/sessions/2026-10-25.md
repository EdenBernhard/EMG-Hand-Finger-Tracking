# Session 2026-10-25 – Rohdaten-Erfassung in Python (wavex)

## Ziel der Session
Einfaches Empfangen der EMG-Rohdaten vom Cometa-WavePlus-System in Python, ohne Bereinigung. Grundlage war das Forschungslogbuch (Erfassungsweg des Altsystems, Empfehlung `pythonnet`).

## Durchgeführt
Die erste Pipeline-Stufe (Erfassung) wurde umgesetzt: Empfang der Rohdaten und unveränderte Speicherung als CSV. Zunächst wurde das .NET-SDK des Altsystems per `pythonnet` angebunden. Nach dem Auslesen der DLL-Metadaten wurde der Code vereinfacht und schließlich auf das offizielle Cometa-Paket `wavex` umgestellt. Zusätzlich wurden Architekturregeln in `CLAUDE.md` festgelegt. Getestet wurde mit nachgebildetem SDK und in einem Lauf ohne angeschlossenen Receiver.

## Code-Änderungen
Commit `adc0e41` (Branch `feat/raw-acquisition`):
- `CLAUDE.md`: Abschnitt „Architektur“ mit vier Stufen (Erfassung → Vorverarbeitung → ML → Ausgabe), Single Responsibility, wenige Abhängigkeiten, Prüfpflicht für generierten Code.
- `src/emg_tracking/acquisition/raw_block.py`: Übergabeformat an Stufe 2, damit die Vorverarbeitung nichts vom SDK importiert.
- `receiver.py`: `CometaReceiver` auf Basis von `wavex`. Callback vor `StartCapturing` registriert, weil im Altsystem danach die ersten Pakete verloren gehen konnten. Puffer wird sofort kopiert, weil `EmgSamples` auf einen wiederverwendeten nativen Puffer zeigt. Gerät wird bei Stopp und Fehler freigegeben.
- `csv_writer.py`: eine Zeile pro Sample (`sample_index`, `host_time_ns`, `sensor_<id>_uV`, `usb_lost_packets`), Dezimalpunkt unabhängig von der Spracheinstellung, weil das Dezimalkomma im Altsystem den Parser gebrochen hat.
- `cli.py`: Aufnahmeschleife; Abbruch, wenn nach 3 s keine Daten kommen, weil `wavex` ein fehlendes Gerät nicht meldet. Leere Aufnahmen werden entfernt.
- `config/acquisition.toml` + `config.py`: `sensor_ids` [1, 2, 4], `event_period_ms` 10; jede Aufnahme speichert eine Kopie der Konfiguration (Reproduzierbarkeit).
- `tests/test_acquisition.py`: 7 Tests ohne Hardware.

## Ergebnisse / Beobachtungen
- Altes SDK `Waveplus.DaqSys` v5.0.7.0 (.NET Framework 4.0), Metadaten per Reflection gelesen: `SamplingRate` nur `Hz_2000`; Event-Periode 10/25/50/100 ms; `EmgHwGain` `g_500`/`g_1000`, Standard-Konstruktor setzt `g_1000`; Event enthält `ScanNumber`, `USBLostPackets`, `SensorRFLostPackets[]`; `DaqSystem` ist `IDisposable`.
- `Samples` ist ein wiederverwendeter Puffer, gültig sind die ersten `ScanNumber` Spalten (aus dem Bytecode abgeleitet, nicht verifiziert). Das Altsystem liest die volle Arraylänge.
- Heruntergeladene DLLs blockiert Windows (`Zone.Identifier`); .NET verweigert das Laden.
- `wavex` 1.3.5 (Cometa srl, Juli 2026): `ctypes`-Wrapper um `WaveX.API.dll`, bringt die DLLs mit, liefert NumPy-Arrays (`EmgSamples` 36 × `ScanNumber`). `WaveX.Sys.dll` enthält WavePlus-Gerätetypen und braucht .NET Framework 4.8.
- Mängel in `wavex` 1.3.5: `GetDeviceState()` liefert immer `None`; einige Setter rufen falsch benannte native Funktionen; keine Verstärkungseinstellung, keine Funk-Paketverluste je Sensor, kein Zustands-Callback.
- Lauf ohne Receiver: DLLs laden, `ConfigureCapture` meldet keinen Fehler, keine Daten → Abbruch nach 3 s.
- Fehler im Altsystem: jede Abtastzeile einzeln asynchron per TCP gesendet und auf die Konsole geschrieben (über 2000-mal/s, Reihenfolge nicht garantiert); fehlende Sensoren als `N/A`; `DaqSystem` nie freigegeben; Paketverluste ignoriert.

## Entscheidungen & Begründung
- Architektur nach Single Responsibility in vier Stufen, mit möglichst wenigen Abhängigkeiten (Eden).
- Altsystem nicht 1:1 übersetzen, sondern vereinfachen und Fehler beheben (Eden).
- Hardware-Verstärkung: SDK-Standard (Eden). Mit `wavex` nicht mehr einstellbar.
- `wavex` statt `pythonnet` mit eigenen DLLs, weil es einfacher ist (Eden: nutzen, „wenn es das einfacher macht“). Nachteil: Verstärkung, Funk-Paketverluste je Sensor und Gerätestatus fallen weg.

## Probleme / Verworfenes
- `pythonnet`-Anbindung mit eigenen DLLs: fertig vorbereitet, verworfen. Die DLLs dürfen nicht mitverteilt werden und müssen entsperrt werden.
- Erste Struktur (Namespace-Suche, CyUSB-Geräteprüfung, Abtastrate als Scheinoption, separate `recorder.py`) war unnötig komplex und wurde vereinfacht.
