# Session 2026-10-29 – Treiber, erste echte Daten und Anlaufphase der Sensoren

## Ziel der Session
Das WavePlus-System erstmals mit Python betreiben: Treiber installieren, den Receiver erkennen lassen und prüfen, ob `wavex` echte EMG-Daten liefert. Dazu die README neu ordnen (Fahrplan ausgelagert) und um eine Anleitung zur Hautvorbereitung erweitern.

## Durchgeführt
Der mitgelieferte USB-Treiber wurde in drei Varianten ausprobiert; erst Version 3.1.0.0 lud unter Windows 11 mit aktivem Secure Boot. Anschließend wurde eine Testaufnahme (`test_aufnahme.py`) mit der in EMG and Motion Tools gespeicherten `.cfg` ausgewertet. Sie lieferte zunächst nur konstante Werte pro Kanal. Mehrere Probeläufe (zusammen mit einem Skript, das die Aufnahme sekundenweise auswertet) zeigten, dass die Sensoren erst etwa 5 s nach `StartCapturing` senden. Die CLI wurde um eine Erkennung dieser Anlaufphase erweitert und mit den Sensoren 5, 6, 7 sowie 1, 2, 4 getestet. Die README wurde umstrukturiert und um Schritte 7/8 ergänzt (Eden).

## Ergebnisse / Beobachtungen
**Treiber**
- Receiver im Rohzustand: `USB\VID_04B4&PID_1004` („Co Generic USB Device“). Nach erfolgreicher Treiberinstallation: `PID_1002`, „EMG and Motion Device“, Status „Gestartet“.
- Treiber 3.0.0.20 (30.01.2017), nur von Cometa srl signiert (GlobalSign-EV-Zertifikat vom 13.10.2016): Gerät mit Problemcode 52 (`CM_PROB_UNSIGNED_DRIVER`, Status 0xC0000428). Secure Boot war aktiv (`UEFISecureBootEnabled = 1`).
- Ein zweiter ausprobierter Treiber hatte laut `pnputil` dieselbe Version und dasselbe Zertifikat und scheiterte genauso.
- Treiber 3.1.0.0 (06.05.2017), signiert von „Microsoft Windows Hardware Compatibility Publisher“ (Attested): lädt bei aktivem Secure Boot. Die Dateien in `Driver/` sind laut Hashvergleich identisch mit dem installierten Treiber.

**Erste Testaufnahmen (`.cfg`, 5 s, Sensoren laut Eden auf 5, 6, 7)**
- Form (36, 9664) bzw. (36, 9665), also 36 Kanäle, ca. 4,8 s. Alle Kanäle konstant (Standardabweichung 0,0), viele bei ±3299,9 µV, Kanäle 17–36 exakt 0.
- Die `.cfg` aktiviert laut `wavex` die EMG-Kanäle 1, 2, 4, 5, 6, 7.
- Mit `CaptureConfiguration` + `set_emg_acq_p(Emg_2kHz_Acc_142Hz)` + `.cfg` schwankten die aktiven Kanäle in einem 3-s-Lauf, in einem anderen 3-s-Lauf derselben Einstellung waren sie flach. Mit dem Wave-X-Modus (`set_emg_acq_x`) waren alle Kanäle flach.
- 12-s-Aufnahme, sekundenweise Standardabweichung der Kanäle 5/6/7: Sekunden 0–4 jeweils 0,0; ab Sekunde 5 Signal (z. B. 633/1062/2219 µV). Dasselbe Verhalten **ohne** `.cfg`. Die Anlaufzeit wurde nur in diesen Läufen gemessen (nicht systematisch vermessen).
- Die Sensoren starten nicht gleichzeitig: Im ersten CLI-Lauf war Sensor 5 über die ganze Aufnahme konstant, Sensor 6 sendete erst 75 Samples nach Sensor 7.

## Interpretation
Eden hat keine eigene Deutung der Signalqualität geäußert. Eine Hypothese von Claude (nicht verifiziert): Schlechter oder fehlender Hautkontakt der Elektroden, weil Pegel (mehrere 1000 µV, nahe der Messbereichsgrenze) und 50-Hz-Anteil typisch für offene Eingänge sind und beide Sensorsätze (1/2/4 und 5/6/7) dasselbe Bild zeigen. Ob die Elektroden bei den Aufnahmen auf der Haut klebten, ist offen.

## Entscheidungen & Begründung
- **Treiber 3.1.0.0 statt 3.0.0.20:** nur diese Version ist von Microsoft signiert; Secure Boot bleibt dadurch eingeschaltet (Alternative, Secure Boot abzuschalten, wurde nicht gewählt).
- **CLI bleibt bei Code + TOML statt `.cfg` laden** (Vorschlag Claude, Eden: „passe CLI und README an“). Begründung: Die `.cfg` ist binär und nicht per Diff vergleichbar; ein Probelauf ohne `.cfg` lieferte nach der Anlaufphase ebenfalls Daten. Die `.cfg` wird nur noch vom Testskript genutzt.
- **Anlaufphase erkennen statt feste Wartezeit** (Vorschlag Claude, von Eden angenommen): Die ca. 5 s sind eine einzelne Messung, keine Herstellerangabe. Das Gate reagiert auf die Daten; `startup_timeout_s = 15` ist nur die Obergrenze.
- **Fahrplan in `docs/ROADMAP.md`** (Eden), README nur für Projekt, Einrichtung, Nutzung.
- **`sensor_ids` auf 5, 6, 7** laut Eden, später wieder 1, 2, 4 (Eden hat die Sensoren gewechselt; in der TOML steht aktuell `[1, 2, 4]`).
